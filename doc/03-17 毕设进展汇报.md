## 项目概述

- **项目名称**：`ZlibValidation `
- **近两周主要新增功能**：
    - 解决了之前功能顺序执行时的数据竞争，实现了多线程单调性检查、超级单元生成功能。
    - 添加了 `compare` 子命令，支持对两个库文件依次进行解析，对比生成的 JSON 文件数据，生成文本表格及对比报告。目前报告格式还需完善。
    - 实现了 `supercell` 子命令，用于生成超级单元映射(.map)文件以供网表生成。
    - 集成了 `zlibboost` 子命令，支持调用开源库特征化工具 zlibboost ，根据配置文件生成特征化的库文件，作为库电气验证的比对项之一。
- **使用方式**：

## 开发进度汇总

### 2025-03-03~2025-03-07

询问师兄，学习了解了华虹、TSMC单元库的层级结构和组织方式。

理解了liberate_lv工具`validate_library`命令所准备的输入文件，.cdl、.sp、.scs、.spi本质都是网表文件，需要经过寄生参数提取 (Layout Parasitic Extraction)以确保精度。model选项需要额外写一个文件去加载网表文件才能被读取。

```tcl
set rundir $env(PWD)
set libdir /home/songzx/examples/mypdk/TSMC65/TSMC65NM_CLN65LP_STDIO_STDCELL/tcbn65lp_220a/0396011_20170308/TSMCHOME/digital/Front_End/timing_power_noise/NLDM/tcbn65lp_220a
set spidir /home/songzx/examples/mypdk/TSMC65/TSMC65NM_CLN65LP_STDIO_STDCELL/tcbn65lp_220a/0396011_20170308/TSMCHOME/digital/Back_End/lpe_spice/tcbn65lp_200a

set_operating_condition -voltage 1.32 -temp 0

set model /home/songzx/examples/test/MODELS/include_FF.sp

set cells {AN2D0 DFQD1}
set subckts {}
set number_of_cells [llength $cells]
for {set count 0} {$count < $number_of_cells} {incr count 1} {
  set cell [lindex $cells $count]
  lappend subckts ${spidir}/${cell}.spi
}

validate_library			\
	-subckts	$subckts	\
	-model      $model      \
	-chain_length	1 	    \
	$libdir/tcbn65lpbc.lib
```

能通过自定义的TCL脚本跑通liberate_lv工具，修改license端口使得Synopsys相关工具能够正常使用。

询问师兄，理解了验证库功能确实隐含了一个k库功能，生成了一些链式spice deck，调用SPICE仿真工具拿去仿真，同时生成一份相同的数字网表给primetime使用。

由于自己生成spice deck、调用仿真器工作量太大，请求师兄整理zliboost代码，对接接口到我的工具中。

对于`validate_library`命令比较的内容是否舍弃原始库数据产生疑问，师兄解答说是pt分析使用Verilog + 原有库。后续要实现自己根据网表生成Verilog代码。了解到可以通过`-chain_length`参数控制生成的链式spice deck的长度。

### 2025-03-10~2025-03-14

- 新增 `supercell` 子命令和 `LibFile::supercell` 方法，用于生成超级单元以供验证。
- 集成了 `zlibboost` 子命令，支持调用开源库特征化工具 [zlibboost](https://github.com/skycrapers/ZlibBoost)。已与开发者取得联系。
- 调整了子命令输出文件的位置为当前目录，避免文件混淆。
- 添加了 `clear` 子命令，方便清理生成的 JSON 文件和日志文件。

- 添加了 `tabulate/table` 库，通过 CMake FetchContent 进行管理，用于生成格式化的表格输出。
- 新建了 `compare.cpp` 和 `compare.hpp` 文件，创建了 `LibraryComparator` 类，用于比较两个库文件的差异。目前实现了读取参考库 JSON 文件的功能。

### 2025-03-15

- 使用 `std::filesystem::path` 重构了 `LibFile` 类的文件路径管理，方便文件路径的拼接和处理。`LibFile` 类添加了成员变量 `basename_`、`filename_`、`libname_`、`jsonname_` 和 `loggername_`，用于存储文件名、库名、JSON 文件名和日志文件名。为了后续开发时变量命名清晰，避免混淆导致错误排查困难。
- 通过作用域 (scope) 管理 `LibFile::parse` 方法中的顶层迭代器的生命周期，提前结束并调用 `si2drPIQuit` 保证资源释放，解决了分析多个库时日志重复输出和数据保存错误的问题。并在此基础上实现了多线程并行功能。`mono`、`supercell`子命令均能并行处理多个库文件，大大提升验证效率。
- 重构了 `spdlog` 日志初始化，返回 logger 对象而不是设置全局默认 logger。保留名为 `APP_NAME` 的全局 logger，用于输出总体提示信息。以适应多线程并行的日志输出需求。

### 2025-03-16

- 针对 `compare` 子命令，增加了对报告文件名的检查，确保其以 `.md` 或 `.txt` 结尾。若不符合，则给出警告并自动添加 `.md` 后缀。
- 完善`LibraryComparator`类，已经可以输出表格，数据数量和商用工具结果一致，但格式还需要进一步调整。
- 新增了 `abstol` 参数，默认值为 0.002ns，用于设置绝对容差，与库验证工具保持一致。
