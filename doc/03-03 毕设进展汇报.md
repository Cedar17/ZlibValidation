## 项目概述

- **项目名称**：`ZlibValidation `
- **目前功能**：验证标准单元库（`.lib` 格式）的有效性，包括解析库文件、生成 JSON 输出以及检查时序信息的单调性。  
- **使用方式**：

```zsh
❯ ./zlibvalidation -h                          
ZlibValidation
Usage: ./zlibvalidation [OPTIONS] [SUBCOMMAND]

Options:
  -h,--help                             Print this help message and exit
  -v,--version                          Display program version information and exit

Subcommands:
  parse                                 Parse the Liberty file and write JSON to a file
  mono                                  Check the monotonicity of timing arc values
```

```zsh
❯ ./zlibvalidation parse -h                                        
Parse the Liberty file and write JSON to a file
Usage: ./zlibvalidation parse [OPTIONS]

Options:
  -h,--help                             Print this help message and exit
  -f,--file TEXT:FILE ... REQUIRED      Specify the lib file to process
  -l,--log TEXT                         Specify the log filename. Default: <input_file>.parse.log
```

```zsh
❯ ./zlibvalidation mono -h                        
Check the monotonicity of timing arc values
Usage: ./zlibvalidation mono [OPTIONS]

Options:
  -h,--help                             Print this help message and exit
  -f,--file TEXT:FILE ... REQUIRED      Specify the lib file to process
  -l,--log TEXT                         Specify the log filename. Default: <input_file>.mono.log
```

## 开发进度汇总

### **基础框架搭建 (2025-01)**

*   **项目初始化**：创建 C++ 空项目，使用 CMake 管理编译，引入外部静态链接库 `libsi2dr_liberty.a` 用于 `.lib` 文件解析。
*   **命令行参数解析**：集成 `CLI11` 库，实现灵活的命令行参数解析功能。
*   **日志系统**：引入 `spdlog` 日志库，实现高效的日志记录，支持分级别输出到文件和控制台。
*   **JSON 支持**：添加 `nlohmann/json` 库，用于 JSON 数据的处理和输出。
*   **版本信息管理**：在 `version.h` 中集成项目版本、作者、构建日期等信息，并由 CMake 自动维护。
*   **工作模式选择**：通过 `--mode` 参数实现 `parse`、`modify`、`mono` 等工作模式的选择。
*   **库文件对象封装**：初步封装 `LibFile` 对象，提供库文件读取、解析和修改的基本方法，以及名称、PVT 信息等公共属性。

### **面向对象重构与核心功能实现 (2025-02-01 ~ 2025-02-15)**

*   **面向对象重构**：采用面向对象编程 (OOP) 思想，对库解析代码进行重构，提高代码可维护性和可读性。
*   **属性与组封装**：
    *   封装 `LibAttribute` 类，用于处理库文件属性的读取，并将属性值转换为 `std::string` 类型。
    *   封装 `LibGroup` 类，用于处理库文件组的读取，提供组名、类别、属性、子组的访问方法。
    *   封装 `AttributesIterator` 和 `GroupsIterator` 类，利用 RAII 机制，实现属性和组的迭代遍历。
*   **模块化编译**：分离类的定义和实现，分别存放于 `include` 和 `src` 目录下，并修改 CMake 配置，实现模块化编译。
*   **JSON 输出功能**：为 `LibFile` 类添加 `writeJsonToFile` 方法，实现将库文件信息输出为 JSON 文件的功能，目前支持 PVT、cell_name、cell_footprint、cell_area 等信息。
*   **LUT 解析**：新增 `parseStringToVector` 辅助函数，用于解析逗号分隔的字符串为浮点数向量，支持 Look Up Table (LUT) 数据的读取。
*   **时序信息解析**：实现 `generateTimingJson` 函数，全面解析库文件中的时序信息，并将其存储到 JSON 对象中。

### **单调性检查功能与结果优化 (2025-02-17 ~ 2025-02-27)**

*   **单调性检查功能**：
*   实现 `LibFile::mono()` 方法，针对 cell_rise、cell_fall、rise_transition、fall_transition 等时序信息，检查其 LUT 数据的单调递增性。
*   支持检查 value 值在 LUT 表格的每一行以及每一列是否保持单调递增。
![PixPin_2025-03-03_11-17-28](https://raw.githubusercontent.com/Cedar17/PicGo_PictureBed/main/img/202503031117671.png)
*   **结果统计与对比**：
*   `LibFile::mono()` 方法增加结果统计功能，输出单调性检查中 `passed` 和 `failed` 的 cell 数量，输出格式参考 `liberate_lv` 工具。
*   以 `sl018_ff_3.96_-40.lib` 和 `tcbn65lpbc.lib` 为例，与 `liberate_lv` 工具进行对比测试，结果一致。
*   **非单调信息提示优化**：对于非单调信息警告，增加输出 when 信息，方便用户定位问题。

### **命令行参数重构与日志优化 (2025-02-25 ~ 2025-02-26)**

*   **命令行参数重构**：使用 `CLI11` 库的子命令功能，重构命令行参数解析，使 `parse`、`mono` 功能更加清晰和独立。
*   **子命令参数自定义**：子命令支持自定义输出文件名、日志文件名，并设置默认值，提高工具的灵活性。
*   **日志信息优化**：改为在 Logger 初始化时打印版本信息，避免在 `-h`，`-v` 等帮助和版本查询时打印冗余信息。

### **多线程并行尝试与问题解决 (2025-02-27 ~ 2025-03-01)**

*   **多线程并行尝试**：尝试使用多线程并行处理多个库文件，提高验证效率。
*   **数据竞争问题排查**：在多线程并行解析过程中，发现 `si2dr_liberty` 库可能存在数据竞争问题，导致程序崩溃。
*   **解耦与问题规避**：修改 `LibFile` 的构造函数和析构函数，将 `si2dr` 库的初始化和销毁放在 `parse` 方法中，使得 `mono` 方法与 `si2dr` 库解耦，规避了多线程并行执行 `mono` 时的潜在问题。
*   **`si2drPIQuit` 警告排查**：排查了 `si2drPIQuit` 警告信息，确认是由于顶层 groups 未及时退出的提示，但不会造成实际内存泄漏。

## 当前状态
- **已实现功能**：
  - 作为命令行程序，提供友好的命令行界面和帮助说明，支持多种参数配置，方便用户使用。
  - 库文件解析并生成 JSON 输出，用时6s左右。
  - 支持4种单调性检查（`cell_rise`、`cell_fall`、`rise_transition`、`fall_transition` ），结果与 `liberate_lv` 一致，用时不到1s，远远快于`liberate_lv`的25s左右。
- **存在问题**：
  - 电压值等浮点数的 JSON 序列化存在精度丢失
  - 尝试多线程并行解析多个单元库，因 `si2dr_liberty` 线程安全问题受阻。
  - 改为顺序读取单元库并解析时，日志打印重复之前库的 PVT 信息，且耗时增加，不如分开单独解析每个文件。
