\hypertarget{md_README_autotoc_md1}{}\doxysection{Description}\label{md_README_autotoc_md1}
Command line tool to validate standard cell libraries in {\ttfamily .lib} format.

{\ttfamily Zlib\+Validation} provides a suite of tools for engineers working with digital IC standard cell libraries in the Liberty format (.lib). It helps ensure library quality, consistency, and facilitates comparison and conversion tasks. Built with C++ for performance and leveraging robust libraries for parsing and command-\/line interaction.\hypertarget{md_README_autotoc_md2}{}\doxysection{Table of Contents}\label{md_README_autotoc_md2}

\end{DoxyItemize}\hypertarget{md_README_autotoc_md3}{}\doxysection{Motivation}\label{md_README_autotoc_md3}
Validating standard cell libraries (.lib) is critical in chip design, but current solutions pose challenges. Commercial tools are expensive, locking out many users (students, startups, researchers), and their closed-\/source nature prevents customization and hinders innovation. This creates a gap, especially for those needing rapid validation within tight resource constraints.

{\ttfamily Zlib\+Validation} aims to fill this gap. It is a {\bfseries{free, open-\/source command-\/line tool}} designed for comprehensive and efficient .lib file validation. Our goals are to\+:


\begin{DoxyItemize}
\item Lower the barrier to entry for library quality assurance.
\item Provide {\bfseries{fast}}, {\bfseries{reliable checks}} (parsing, consistency, function, parameters, comparison).
\item Enable {\bfseries{transparency}}, {\bfseries{customization}}, and {\bfseries{community collaboration}} through open source.
\item Bridge the divide between academic research and industrial needs in validation technology.
\end{DoxyItemize}\hypertarget{md_README_autotoc_md4}{}\doxysection{Installation}\label{md_README_autotoc_md4}
{\ttfamily Zlib\+Validation} is designed to be easily built and run directly from source {\bfseries{without requiring administrator}} ({\ttfamily sudo}) {\bfseries{privileges}} on Linux systems. This makes it ideal for environments where users have restricted permissions. The recommended installation method is building from source.\hypertarget{md_README_autotoc_md5}{}\doxysubsection{Prerequisites}\label{md_README_autotoc_md5}
Before you begin, ensure you have the following installed on your {\bfseries{Linux}} system\+:


\begin{DoxyItemize}
\item {\bfseries{Git\+:}} To clone the repository.
\item {\bfseries{C++ Compiler\+:}} C++20 standard support required (e.\+g., GCC \texorpdfstring{$>$}{>}= 12). Developed with GCC 14.\+2.\+0.
\item {\bfseries{CMake\+:}} Version 3.\+25 or higher (versions after 4.\+0.\+0 may exhibit compatibility issues).
\item {\bfseries{Ninja}} (recommended) or {\bfseries{Make}}\+: Build systems. Ninja is preferred for its speed.
\end{DoxyItemize}\hypertarget{md_README_autotoc_md6}{}\doxysubsection{Optional Pre-\/requisites}\label{md_README_autotoc_md6}

\begin{DoxyItemize}
\item {\bfseries{ccache\+:}} Optional but recommended for speeding up recompilation. Install it via your package manager (e.\+g., {\ttfamily conda install conda-\/forge\+::ccache}).
\item {\bfseries{lld\+:}} Optional but recommended for faster linking. Install it via your package manager (e.\+g., {\ttfamily conda install conda-\/forge\+::lld}).
\end{DoxyItemize}\hypertarget{md_README_autotoc_md7}{}\doxysubsection{Building from Source (\+Recommended Method)}\label{md_README_autotoc_md7}
Follow these steps to compile {\ttfamily Zlib\+Validation} in your user directory\+:


\begin{DoxyEnumerate}
\item {\bfseries{Clone the repository\+:}} 
\begin{DoxyCode}{0}
\DoxyCodeLine{git clone -\/-\/single-\/branch -\/-\/branch master https://github.com/Cedar17/ZlibValidation.git}
\DoxyCodeLine{cd ZlibValidation}

\end{DoxyCode}

\item {\bfseries{Configure the build using CMake\+:}} Create a build directory and run CMake from within it. This keeps build files separate from your source code. 
\begin{DoxyCode}{0}
\DoxyCodeLine{mkdir build}
\DoxyCodeLine{cd build}
\DoxyCodeLine{\# Use Ninja as the build system (recommended):}
\DoxyCodeLine{cmake .. -\/G Ninja}
\DoxyCodeLine{\# or if you prefer Make:}
\DoxyCodeLine{cmake .. -\/G "{}Unix Makefiles"{}}

\end{DoxyCode}
 {\itshape Note\+: No {\ttfamily sudo} is needed here.}
\item {\bfseries{Compile the project\+:}} Use {\ttfamily ninja} to build the executable. If you chose Make, use {\ttfamily make} instead, the {\ttfamily -\/j} flag speeds up compilation by using multiple processor cores. 
\begin{DoxyCode}{0}
\DoxyCodeLine{\# If you used Ninja:}
\DoxyCodeLine{ninja}
\DoxyCodeLine{\# or if you used Make:}
\DoxyCodeLine{make -\/j\$(nproc) \# Adjust \$(nproc) or use a specific number like -\/j8 for multi-\/threading}

\end{DoxyCode}

\item {\bfseries{Locate the Executable\+:}} Upon successful compilation, the {\ttfamily zlibvalidation} executable will be located inside the {\ttfamily build} directory\+: {\ttfamily ./build/zlibvalidation}. 
\begin{DoxyCode}{0}
\DoxyCodeLine{\# Check the executable version:}
\DoxyCodeLine{./zlibvalidation -\/-\/version}

\end{DoxyCode}
